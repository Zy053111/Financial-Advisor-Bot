2. system architecture -- show architecture diagram

To achieve fault isolation and operational scalability, the system is engineered using a decoupled, four-layer architecture. 

Layer 1 handles real-time historical market ingestion via the yfinance API.

Layer 2 is our quantitative core, implementing a custom Gymnasium financial environment and a stable Proximal Policy Optimization (PPO) network to generate asset weights.

Layer 3 acts as our middleware interpreter, serializing raw numeric vectors into structured JSON payloads to drive local, edge-hosted large language models via Ollama.

Layer 4 delivers the presentation views through a decoupled secure Django REST API and an interactive React.js client dashboard.

--- show dfd ---
As detailed in this Level-1 Data Flow Diagram, a single portfolio recommendation cycles seamlessly across subsystem boundaries. Raw prices are ingested, cleaned via data imputation (ffill/bfill), and transformed into stationary log returns, RSI, and MACD indicators. These indicators form  multi-dimensional state tensor. The PPO model evaluates this matrix, applies an exponential Softmax normalization layer to output a safe asset weight simplex, and passes this telemetry data to local Llama-3 model to generate conversational plain-English prose.

4. --- show dual-track---
To ensure maximum engineering validity, the system deploys a strict, dual-track validation framework.

Track 1 routes my optimized portfolio weight outputs straight into an event-driven Backtrader engine. Unlike idealized models, this pipeline introduces a 0.1% fixed trading fee and execution slippage penalties to measure true real-world financial efficacy against simple buy-and-hold baselines.

Track 2 handles qualitative accessibility testing, streaming the generated conversational prose to a five-user non-technical retail cohort to calculate official system usability scale (SUS) scores. This ensures my interface builds genuine user trust.
